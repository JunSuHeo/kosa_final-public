# 작업 인계

다음 담당자가 대화 전체를 다시 읽지 않고 실제 저장소 상태에서 작업을 이어갈 수 있도록 정리한다.

## 절차

1. [루트 지침](../../../AGENTS.md), [기록 규칙](../../workflow/README.md)과 해당 작업의 기존 README를 읽는다. `.agent-local.md`·대화에서 담당 팀원을 확인하고 기존 기록을 이어 쓴다. 공동 작업이면 대표 기록과 참여자의 기록을 연결한다.
2. 현재 브랜치·HEAD·`git status --short`·관련 diff를 확인한다. 작업 전부터 있던 변경과 이번 변경을 구분한다. 커밋 여부·원격 반영 여부는 확인한 범위에서만 쓴다.
3. 기존 작업 README의 계획·결정·검증 근거를 유지하고 아래 재개 정보를 갱신한다. 작은 작업은 README 하나면 충분하며 큰 작업에서 필요할 때만 별도 인계 문서를 연결한다.

| 재개 정보 | 남길 내용 |
| --- | --- |
| 대상 | 담당 팀원, 작업 목표·현재 단계, 관련 Issue/PR URL 또는 연결 없음 |
| 코드 기준 | 브랜치·기준 커밋·현재 HEAD, 이번 변경 파일과 미커밋·미추적 상태 |
| 결과와 판단 | 완료된 동작, 중요한 결정·짧은 이유, 제외 범위 |
| 검증 | 실제 실행한 명령·환경·결과·근거 경로, 실패·미실행·미확인 |
| 다음 행동 | 이어서 할 구체적인 첫 행동, 필요한 선행 작업·미결정 사항 |

4. [프로젝트 안내](../../../PRJ/agents/project.md)의 구조·사용법이나 계약이 바뀌었으면 해당 소유 문서에도 반영됐는지 확인한다. 담당 팀원 목록과 공통 작업 목록에서 기록으로 이동할 수 있게 한다.
5. 완료 조건을 실제로 만족했을 때 완료로 표시한다. 재개가 필요하면 진행 중·입력 대기 등 실제 상태와 남은 일을 기록한다. 사용자에게는 변경 결과·검증·남은 작업을 간결하게 보고한다.

## 기록 경계

내부 사고 과정 전문·인증 정보·비공개 코드 원문은 저장하지 않는다. 판단은 근거와 결정 요약으로 남긴다. 예시 명령, 과거 통과 기록, 이번 실행을 구분한다. 없는 Issue·PR·검증 결과를 만들지 않는다.

인계 기록을 작성했다고 Issue를 종료하거나 PR을 게시·병합하지 않는다. 사용자가 해당 외부 작업을 요청한 경우에만 실제 도구·권한과 실행 결과를 확인한다.
