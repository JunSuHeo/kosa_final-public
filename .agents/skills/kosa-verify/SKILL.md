# 변경별 검증

변경한 동작의 완료 조건을 확인하고, 통과·실패·미실행·미확인을 실행 근거와 함께 기록한다.

## 검사 선택

[루트 지침](../../../AGENTS.md), [프로젝트 안내](../../../PRJ/agents/project.md), [실행 안내](../../../PRJ/README.md)와 관련 영역 문서를 확인한다. `git status`와 diff를 읽어 이번 변경과 기존 변경을 구분하고 새로 만든 미추적 파일도 검사 범위에 넣는다. 아래 명령은 현재 저장소의 기본값이므로 실행 전에 실제 파일과 전제를 확인한다.

| 변경 | 검증과 실행 위치 |
| --- | --- |
| 안내·기록·공용 스킬 | 로컬 링크·앵커·경로·명령 전제·공통 지침 보존·Markdown 형식 확인. 스킬은 YAML name/description과 폴더명 일치·사용 조건·참조를 확인하고 작성 도구의 validator가 있으면 사용 |
| UI 코드·타입·빌드 | `PRJ/frontend/`에서 재현 설치 `npm ci`, `npm run build`. 상호작용을 바꾸면 관련 mock E2E도 확인 |
| 서버·DB migration·API | `PRJ/`에서 격리 Compose 프로젝트를 지정한 뒤 `docker compose --profile test run --build --rm test` |
| 사용자 흐름·UI/API 통합 | `PRJ/`에서 `sh scripts/e2e.sh`로 격리 mock E2E |
| API·snapshot 계약 | 서버 schema·UI 타입·docs/spec schema/예시·관련 테스트를 대조. 계약 검사가 자동화됐다고 가정하지 않음 |
| 인프라·복구 | [infra 안내](../../../PRJ/agents/infra.md)와 실제 검증 스크립트의 환경·범위를 확인하고 필요한 격리 검사 선택 |

문서만 변경한 경우 문서 정적 확인으로 검증한다. 존재하지 않는 lint 명령이나 아직 제안 단계인 공통 검증 실행기를 호출하지 않는다. 같은 검사 범위를 더 크게 반복하는 것은 새 변경·실패·미확인 문제가 있을 때만 한다.

## 실행 전제

- backend 테스트는 별도 PostgreSQL `studio_test`와 mock 인증/AI를 사용하며 테이블을 TRUNCATE한다. `STUDIO_COMPOSE_PROJECT`를 작업별로 구분해 다른 테스트와 DB를 공유하지 않는다. 서비스 DB에 직접 pytest를 연결하지 않는다.
- 현재 e2e.sh는 프로젝트 `planning-studio-e2e`와 포트 `54332/8011/5175`를 고정한다. 같은 호스트에서 다른 실행과 겹치면 겹치는 실행을 종료하지 말고 순서를 조정한다. 외부 환경변수만으로 이 고정값이 바뀐다고 가정하지 않는다.
- Docker·의존성·필요한 환경 파일이 없으면 해당 검사와 이유를 미실행으로 기록하고 가능한 독립 검사를 수행한다. 서비스 설정·키·모델을 임의로 바꾸지 않는다.
- live smoke·평가는 비용과 데이터 생성을 수반하므로 사용자 요청 범위에 포함될 때 실행하고 mock 결과와 구분한다.

## 결과 기록

[작업 기록](../../workflow/README.md)에 실행 위치, 실제 명령, 모드·격리 환경의 비민감 식별값, 종료 코드·관찰 결과, 관련 근거를 남긴다. 비밀값이나 전체 환경 출력은 남기지 않는다. 실패가 있으면 원인·수정·재검증을 이어 쓰고 미실행 필수 검사를 통과로 보고하지 않는다.

`git diff --check`로 추적 파일의 공백 오류를 확인하고 미추적 파일은 별도로 확인한다. 완료 보고에는 무엇을 검증했는지와 남은 한계를 적는다. 파일 검사 통과만으로 스킬의 실제 선택·행동이나 제품의 의미 품질까지 검증했다고 주장하지 않는다.
