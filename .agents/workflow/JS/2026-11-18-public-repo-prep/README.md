# 저장소 공개 전 점검

- 날짜: 2026-11-18 (Asia/Seoul)
- 담당 팀원: JS
- 참여 AI: Codex
- 목표: 공개용 파일에서 비밀값·내부 자료·생성 파일을 제외하고 팀원용 설정 예제를 보존한다.
- 기준: 로컬 main `bc17958`, 점검 당시 원격 main `506f687`. 시작 전 작업 트리에 별도 Supabase 및 하네스 변경이 있었다.
- 계획: 현재 파일과 로컬·원격 이력 검사 → 무시 규칙 적용과 추적 해제 → 공유용 파일 집합 재검사.

## 변경 사항

- 루트와 PRJ의 Git 제외 규칙에 로컬 설정·키·덤프·실행 결과·업무 저장소 검증 자료·생성 파일을 추가했다.
- 현재 추적된 제외 대상 171개는 `git rm --cached`로 다음 커밋에서 제외했다. 원본은 로컬에 보존했다.
- PRJ Docker 빌드 컨텍스트에서도 환경 파일과 키 파일을 제외한다. 공개 문서의 내부 자료 참조는 파일명으로 바꾸고 개인 경로·프로젝트 ID를 제거했다.
- 원격 설정 및 이력은 조회만 했다. 작업은 미커밋 상태다.

## 공개 조건

- 로컬과 원격의 과거 커밋 `eb6df9d`의 `PRJ/.env`에서 API 키가 탐지됐다. 해당 키는 제공자에서 폐기·교체하고, 과거 자료를 공개하지 않으려면 정리한 소스로 새 공개 저장소를 만들거나 팀과 기존 이력 정리를 조율한다.
- 공개 전 GitHub Actions 이력·첨부 및 이슈·PR 게시물도 별도로 확인한다. 이 저장소의 Issue 워크플로에는 self-hosted runner가 지정되어 있다.
- 팀원에게는 `PRJ/.env.example`, `PRJ/.env.supabase.example`, `.agent-local.example.md`를 공유한다. 운영 DB URL과 API 키는 필요한 팀원에게만 비밀 저장소로 전달한다.

## 검증 결과

- Gitleaks 8.30.1로 로컬 브랜치·태그·원격 추적 이력과 조회 시점 원격 미러 이력을 확인했다. 양쪽에서 과거 `PRJ/.env`의 동일한 탐지 1건이 나왔다. 원격 main은 `PRJ/.env`를 추적했고 `PRJ/.env.supabase`는 추적하지 않았다.
- 공개 후보 파일 집합을 임시 위치에 복사해 Gitleaks를 실행했고 탐지 0건이었다. 추적 해제 대상 171개가 로컬에 남아 있고 공유용 예제·Compose·migration이 후보 파일에 포함되는지 확인했다.
- 임시 복제본에서 예제 환경 파일로 기본 및 Supabase Compose의 `config -q`가 통과했다. Supabase 검증에는 가짜 URL을 사용했다.
- `git diff --check`, `git diff --cached --check`, 공개 문서의 제거 대상 링크 검사 통과. PR·이슈 본문, Actions 로그와 첨부, GitHub 접근 설정은 미확인이다.

## 공개용 이력 분리

- 원격 main `506f687`은 로컬 HEAD의 후속 커밋이었다. 충돌이 없는 워크플로 엔진·설정·문서 13개 경로를 공개용 파일 집합에 반영했다.
- 별도 로컬 저장소 `../kosa_final-public`에 공개용 트리를 만들었다. 개별 팀 작업 기록, 실제 환경값, 내부 실행 자료 및 self-hosted Issue Actions 설정을 제외했다. 원래 저장소의 인덱스·원격은 보존했다.
- 초기 커밋 `29304e4` 하나와 main 브랜치만 있는 것을 확인했다. Gitleaks 8.30.1의 파일 검사 및 전체 Git 이력 검사에서 모두 탐지 0건이다.
- 복사한 트리의 격리 Compose backend 테스트는 35개 통과했다. 워크플로 unittest는 macOS 기본 임시 경로에서 실패했고, 해당 운영 환경과 일치하는 Linux 컨테이너에서 227개 실행 후 성공했다.
- 공개용 저장소에 리모트를 등록하거나 푸시하지 않았다. 기존 비공개 저장소의 가시성과 이력도 변경하지 않았다.
