# ECC 방식의 작업 인계와 스킬 평가

- 날짜 2026-11-19 (Asia/Seoul)
- 담당 팀원 JS
- 목표는 팀원이 작업을 이어받기 쉽게 하고 공용 스킬을 바꾼 뒤 검증 선택과 보고가 잘 적용되는지 확인하는 것이다.
- 범위는 팀 하네스 문서, 고정 평가 사례와 이번 평가 기록이다.

## 계획

1. 작업 단계별 인계 기록을 공용 템플릿에 연결한다. 조사·구현·검증 인계를 작업 기록에서 확인한다.
2. 고정 과제와 판정표를 분리한다. 새 평가 세션에 과제만 전달해 결과를 판정표로 확인한다.
3. 반복 이슈의 팀 검토·반영 절차를 공용 문서와 온보딩에서 찾을 수 있게 연결한다.

## 평가 결과와 인계

- 입력 및 판정은 [Studio PR 검증 스킬 회귀 평가](../../../evals/studio-pr-check/README.md)를 사용했다.
- 실행 도구는 Codex 에이전트이며 최종 과제 기준으로 사례당 1회 실행했다. A의 예비 평가 뒤 검증에서 발견한 프런트엔드 파일 경로를 실제 경로로 수정하고 새 세션에서 다시 확인했다. 저장소 기준 커밋은 `506f687`, 작업 트리에서 평가한 스킬의 Git 파일 해시는 `6c593be0b9766a506896e1d0fe432601559c2945`다.
- 사례별 에이전트는 해당 스킬과 필요한 제품 문서·명령 정의만 읽고 검증 계획과 PR 보고 예시를 반환했다. 현재 변경에서 제품 테스트와 가상 PR 검증은 실행하지 않았다.
- ECC의 [단계별 맥락 정리](https://github.com/affaan-m/ECC/tree/v2.2.3/skills/strategic-compact)와 [사례 기반 평가](https://github.com/affaan-m/ECC/tree/v2.2.3/skills/eval-harness)를 팀 방식에 맞췄다. 반복 문제는 공용 문서의 검토 절차로 처리한다.
