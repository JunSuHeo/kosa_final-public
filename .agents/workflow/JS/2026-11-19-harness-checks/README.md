# 하네스 검증과 회귀 평가 구축

- 담당 팀원 JS, 작업 에이전트 Codex
- 목표는 팀이 같은 검증 명령을 실행하고, 격리 테스트와 개발 맥락을 재현할 수 있게 하는 것이다.
- 완료 조건은 아래 여섯 단계를 구현하고 실제 확인 결과를 남기는 것이다.

## 계획

1. 하네스 상태 점검 → 현재 경로, 담당자 폴더, 누락 스킬을 판별한다.
2. 공통 검증 명령 → 체크 종류별 종료 코드와 결과를 기록한다.
3. 일반 PR 검증 CI → 같은 검증 명령을 GitHub 호스팅 러너에서 실행한다.
4. 환경 격리 → 실행별 이름, 임의 포트, 별도 PostgreSQL과 테스트 전용 환경을 확인한다.
5. 맥락 기록 → 로컬 지침과 자동 실행에 제공된 파일의 해시를 기록한다.
6. 회귀 평가 → 실제 API 계약과 저장 계약을 비교하고 범위·실행·보고 사례를 검증한다.

## 범위

기존 Issue 승인 workflow의 실행·게시 정책을 유지한다. 자동 실행에는 컨텍스트 증거만 추가한다. 공통 기록 README의 스킬 안내는 루트 목록을 참조하도록 중복 표만 정리한다.

## 변경과 검증

| 단계 | 구현 및 확인 |
| --- | --- |
| 하네스 상태 | 필수 안내, 링크·앵커, 스킬 목록, 개인 팀원 경로 검사 통과. 공용 안내의 사라진 스킬 링크를 루트 9절 참조로 정리했다. |
| 공통 검증 | `workflow.checks.harness all` 전 항목 종료 코드 0. 프런트 빌드와 격리 PostgreSQL 테스트 35개 통과. [실제 명령 결과](verification.json) |
| 일반 PR CI | YAML 구조와 `auto --base HEAD~1 --head HEAD --list` 확인. GitHub Actions 실행 및 필수 검사 설정은 미확인이다. |
| E2E 격리 | 같은 체크아웃에서 동시에 두 번 실행해 별도 프로젝트·볼륨에서 각각 7개 통과했다. 이후 최종 전체 검사에서도 E2E 7개 통과, 생성한 컨테이너·볼륨·빌드 이미지 정리 확인. |
| 개발 맥락 | [로컬 해시 기록](context.json) 생성. 모의 런타임에서 실제 프롬프트 문서 해시를 기록하고 복사 범위 밖 스킬을 제공했다고 보고하지 않는지 회귀 검사했다. |
| 회귀 평가 | 저장 계약 3개 및 예시 2개 일치. 임시 OpenAPI 사본에서 누락된 경로 탐지. 하네스 검사 4개와 Linux 컨테이너의 런타임 회귀 228개 통과. 실제 모델 행동 평가는 실행하지 않았다. |

macOS 임시 폴더의 별칭 경로 때문에 증거 검사에 실패한 사례는 실제 경로를 전달해 해결했다. 게시 준비 회귀는 기존 런타임의 Linux 제한이 있어 테스트 소스만 읽기 전용으로 마운트한 네트워크 없는 Linux 컨테이너에서 확인했다. 기존 제품 테스트에서는 의존성 deprecation 경고가 1건 있었다.

## 후속 변경

사용자 요청에 따라 루트 `workflow/`에 추가한 검사·맥락 기록·회귀 평가와 런타임 변경을 되돌렸다. 삭제한 스크립트에 의존하던 PR 검증 파일과 지침 링크도 제거했다. 위 표는 되돌리기 전 실행 기록이다. `PRJ/`의 격리 E2E와 계약 검사 스크립트는 계속 사용할 수 있다.
