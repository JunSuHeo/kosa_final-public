# 기획실 진행 표시 갱신 수정

- 날짜 2026-11-28 (Asia/Seoul)
- 상태 완료
- 담당 팀원 JS
- 참여 AI 에이전트 Codex
- 목표 생성이 끝난 초안을 새로고침 없이 표시한다.
- 완료 조건 상태 조회가 1.3초보다 오래 걸려도 응답을 반영하고 검토 대기 중 조회를 멈춘다.
- 변경 범위 프로젝트 상세 상태 조회와 브라우저 회귀 테스트

## 읽은 근거

- `PRJ/AGENTS.md`, `PRJ/rules/project.md`, `PRJ/rules/frontend.md`, `PRJ/docs/spec/README.md`
- `PRJ/frontend/src/App.tsx`, `PRJ/frontend/tests/app-journey-regressions.spec.ts`

## 계획

1. 지연된 상태 응답을 브라우저 테스트로 재현하고 기존 구현의 실패를 확인한다.
2. 이전 조회가 끝난 후 다음 조회를 예약하고 화면 전환 시 예약과 진행 중인 조회를 취소한다.
3. 회귀 테스트, 프런트엔드 빌드, 격리된 생성 흐름을 검증한다.

## 원인과 변경

- 초안이 검토 대기로 저장된 뒤에도 브라우저가 생성 중 화면을 유지했다. 고정 1.3초 주기로 프로젝트 상세 요청을 시작했고, 새 요청이 시작되면 대기 중인 이전 응답은 요청 번호 검사를 통과할 수 없었다.
- 상태 요청을 한 번씩 실행한다. 성공 또는 실패로 요청이 끝나면 다음 조회를 예약한다. 작업 상태·프로젝트·계정이 바뀌거나 화면을 나가면 진행 중인 조회와 예약을 정리한다.
- 브라우저 회귀 테스트는 최초 실행 중 응답 다음부터 완료 응답을 1.8초 지연시킨다. 완료된 초안 표시, 진행 버튼 제거, 최대 동시 조회 1건을 확인한다.

## 검증

- 변경 전 Playwright에서 초안 카드가 나타나지 않아 새 회귀 테스트가 실패했다.
- 변경 후 같은 회귀 테스트에서 초안이 표시됐다.
- 최종 프런트엔드 TypeScript 및 Vite 빌드가 통과했다.
- 최종 소스로 `PRJ/`에서 `sh scripts/e2e.sh tests/app-journey-regressions.spec.ts tests/app-drafts.spec.ts tests/business-journey.spec.ts`를 실행했다. 테스트 전용 DB·Auth와 mock AI로 24건 모두 통과했고 격리 환경을 정리했다.
- 로컬 웹 컨테이너를 새 이미지로 교체한 뒤 웹 경유 `/health` 정상 응답, 기존 API·worker 컨테이너 ID 유지, 새 브라우저 번들과 기존 초안 화면을 확인했다.

## 결과·인계

- 수정 범위는 `App.tsx`의 프로젝트 상태 조회, 해당 회귀 테스트, 프런트엔드 개발 안내다.
- 테스트 환경에서 지연 조건을 재현했다. 기존 Supabase 프로젝트에서는 새 초안 생성을 실행하지 않고 저장된 초안 표시를 확인했다.
