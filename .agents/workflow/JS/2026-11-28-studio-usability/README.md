# Studio 현업 사용성 개선

- 담당 팀원은 JS. Codex가 구현과 검증 담당.
- 목표는 사용성 평가에서 재현한 여섯 문제 해결.

## 계획 및 완료 조건

1. 확인본 목록 진입 → 모바일에서 저장 문서 확인.
2. 검토 시 주의사항 표시 → 체크박스와 대표 항목을 함께 확인.
3. 방문 이력 → 뒤로 가기로 이전 산출물 탭 복원.
4. 화면 시안 → 모바일에서 전체 폭과 검토 복귀 동작 확인.
5. 대화 기록 → 초안 요청 이후 기존 답변이 한 번만 표시되는지 확인.
6. 미배정 홈 → 실제 업무 배정에 전달할 정보와 일관된 안내 확인.

## 구현 인계

- 목록의 확인본 보기와 산출물 주소·이력은 프런트엔드에서 처리한다. 프로젝트를 만든 뒤 설명 화면 주소를 교체하고, 현업 확인본과 초안의 선택을 뒤로 가기에서 복원한다.
- 검토 안내는 확인 사항 개수와 첫 항목을 저장 동작 옆에 배치했다. 전체 확인 사항 열기는 제목에 초점을 옮긴다. 모바일 화면 시안은 캔버스 폭을 기준으로 축소하고 검토 복귀를 한 줄로 표시한다.
- 대화형 생성과 수정은 직전 사용자 메시지를 재사용할 때 중복 저장을 건너뛴다. 실제 대화 전송과 신규 요청은 기존 기록 경로를 사용한다.
- 업무 미배정 홈에서 관리 권한이 있는 사용자는 설정으로 이동한다. 일반 사용자는 사내 IT 담당자에게 로그인 아이디와 요청할 업무명을 전달하도록 안내한다. 조직별 연락처는 확인되지 않았다.

## 검증 인계

- 프런트엔드 TypeScript·Vite 프로덕션 빌드와 `git diff --check` 통과.
- 루트 `make test`에서 격리 PostgreSQL 백엔드 테스트 112개 통과.
- 초기 브라우저 테스트에서 대화 중복과 미배정 홈 문제를 재현했다. 검토 화면 진입 방식 때문에 질문 대기 화면의 기존 뒤로 가기 검사가 한 차례 실패해 이력 갱신을 수정했다. 이후 확인 사항 개수와 저장 상태에 대한 테스트 선택자도 실제 UI에 맞게 수정했다.
- PRJ에서 `sh scripts/e2e.sh tests/business-journey.spec.ts tests/workflow-review.spec.ts tests/app-journey-regressions.spec.ts` 최종 27개 통과. 격리 DB와 테스트 인증·mock AI로 모바일 390×844의 문서 이동, 가로 폭, 저장 상태, 목록 재진입과 새로고침을 확인했다.
- 서비스 배포 및 실제 단말 검증은 미실행.
