# 에이전트 작업 기록

`PRJ/`는 서비스 개발 영역, `.agents/workflow/`는 팀원별로 AI와 진행한 작업·결정·검증·인계 기록 영역이다. JS/SY/SW는 팀원 구분이며 AI 에이전트 이름이 아니다. 사용자 데이터나 제품 내 역할별 검토 결과는 저장하지 않는다.

## 담당 팀원 설정

각자의 체크아웃 루트에 `.agent-local.md`를 두고 담당 팀원과 기록 경로를 정의한다. [공유 예시](../../.agent-local.example.md)를 처음 한 번 복사한 뒤 `미설정` 두 항목을 자신의 코드(JS/SY/SW)와 해당 경로(`.agents/workflow/JS/` 등)로 바꾼다.

```sh
# kosa_final/에서 실행. 기존 개인 설정은 보존한다.
test -f .agent-local.md || cp .agent-local.example.md .agent-local.md
```

루트 AGENTS.md의 지침에 따라 에이전트는 작업 시작 시 이 파일을 읽는다. 파일이 없거나 값이 잘못되면 현재 대화에서 명시한 담당자를 사용하고, 대화에도 없으면 사용자에게 확인한다. 이 파일은 Git에서 제외되므로 다른 팀원에게 공유되지 않는다. 팀원이 각자 별도 체크아웃을 사용한다는 전제다.

## 폴더와 기록 방식

담당 팀원의 `JS/`, `SY/`, `SW/` 아래 작업마다 `YYYY-MM-DD-짧은작업명/`을 만든다. 날짜는 Asia/Seoul 기준이며 같은 팀원 폴더에서 이름이 겹치면 숫자를 덧붙인다. 단순한 작업은 작업 README.md 하나로 충분하다.

```text
.agents/workflow/
├── README.md                       # 팀 공통 규칙·작업 목록·공통 결정
├── JS/
│   ├── README.md                   # JS의 작업 목록
│   └── YYYY-MM-DD-task-name/
│       ├── README.md               # 목표·담당·결과·검증·인계
│       ├── agents/                 # 여러 AI가 참여할 때만 생성
│       │   ├── frontend.md
│       │   └── backend.md
│       └── logs/                   # 필요할 때 정제한 실행 근거
├── SY/
│   ├── README.md
│   └── YYYY-MM-DD-task-name/
│       └── README.md
├── SW/
│   ├── README.md
│   └── YYYY-MM-DD-task-name/
│       └── README.md
└── 2026-11-17-harness/              # 구조 도입 전의 초기 공통 기록 보존
    └── README.md
```

- 시작할 때 담당 팀원·참여 AI·목표·완료 조건·담당 범위·짧은 계획을 작성한다. 팀원과 AI의 역할을 구분한다.
- 의미 있는 결정·실패는 확인한 사실, 선택한 방법, 짧은 이유와 대안으로 요약한다. 내부 사고 과정 전문이나 원시 대화 전체를 기록하지 않는다.
- 명령 실행 디렉토리, 비민감 환경 전제, 종료 코드·관찰 결과를 남긴다. 예상과 실제, 실패와 미실행을 구분한다.
- 완료 시 변경 파일·검증·미확인·후속 작업을 정리한다. 실패 기록은 남기고 후속 결과를 덧붙인다.
- 여러 에이전트가 실제 참여하면 각자 파일을 사용하고 공통 README에서 링크한다. 담당 파일과 의존성을 명시한다. 병렬 에이전트 사용 여부는 사용자 요청과 실행 환경 규칙을 따른다.
- 다른 작업의 기록을 지우지 않는다. 인계받을 때 기존 기록을 읽고 이어진 결정·변경을 추가한다.
- 작업 README는 담당 팀원 폴더의 README에 링크한다.
- 공동 작업은 대표 담당자의 작업 README 하나를 기준으로 정한다. 다른 팀원이 별도 작업 기록을 작성하면 대표 기록과 서로 링크하고 각자의 변경 범위·의존성을 명시한다.
- 팀 공통 결정은 이 문서에 짧게 요약하고 상세 작업 기록을 링크한다. 기존 루트의 초기 공통 기록은 보존하고 신규 작업은 팀원 폴더에 만든다.

## 작업 README 템플릿

빈 항목은 `해당 없음` 또는 `미확인`으로 명시한다.

```markdown
# 작업 제목

- 날짜: YYYY-MM-DD (Asia/Seoul)
- 상태: 진행 중 / 완료 / 중단 / 입력 대기
- 담당 팀원: JS / SY / SW 중 실제 담당자
- 참여 AI 에이전트·담당 범위:
- 공동 작업의 대표 기록·관련 팀원 기록: 해당 없음 또는 링크
- 요청·목표:
- 완료 조건:
- 변경 범위:

## 읽은 근거

- AGENTS.md, PRJ/AGENTS.md, PRJ/agents/해당영역.md
- 관련 계약·소스·테스트 경로

## 계획

1. 작업 → 확인 방법

- 선택과 이유:
- 실패·대안·범위 변경:

- 경로: 변경 내용
```

## 기록에서 제외할 정보

API 키·비밀번호·JWT·쿠키·DB 접속 비밀·개인정보·비공개 코드 원문을 복사하지 않는다. 비밀값을 제거한 최소 재현과 관찰 요약을 남긴다. 민감한 원본이 필요한 경우 버전 관리 밖의 제한된 경로에 보관한다. 서비스 .env나 DB dump를 이곳에 두지 않는다.

구조·사용법이 바뀌면 기록뿐 아니라 [PRJ/agents/project.md](../../PRJ/agents/project.md)와 해당 영역 문서도 갱신한다.

## 공용 스킬 관리

팀 공용 원본은 루트 `.agents/skills/`다. 각 스킬은 필수 SKILL.md와 실제로 필요한 경우에만 스크립트·참조 자료를 포함한다. 공용 절차는 기존 제품 문서를 링크하며 복제하지 않는다.

| 스킬 | 사용 예시 |
| --- | --- |
| [kosa-issue-start](../skills/kosa-issue-start/SKILL.md) | `$kosa-issue-start`로 지정 Issue의 범위·완료 조건을 확인하고 개발 준비 |
| [kosa-verify](../skills/kosa-verify/SKILL.md) | `$kosa-verify`로 현재 변경 영역에 맞는 검사 수행·결과 기록 |
| [kosa-handoff](../skills/kosa-handoff/SKILL.md) | `$kosa-handoff`로 현재 작업의 변경·검증·다음 행동 정리 |

- 변경이 필요하면 요청 범위와 기대 동작을 Issue 또는 현재 작업 기록에 남기고 작업 브랜치에서 수정한다. GitHub에 게시하는 작업은 사용자가 요청한 범위에서 수행한다.
- PR에는 변경 이유, 사용 예시·기대 결과, 실제 검증과 한계를 적고 다른 팀원이 리뷰한다. name·description의 사용 조건과 참조 경로도 확인한다.
- name/description·형식을 검사하고 실제 요청으로 필요한 절차가 선택되는지 확인한다. 형식 통과와 행동 검증은 구분한다. 서비스·외부 데이터를 바꾸는 예시는 격리 환경과 해당 작업의 허용 범위를 따른다.
- 병합된 커밋을 각자의 체크아웃에 반영해 같은 코드·스킬 버전을 사용한다. 재현이 필요하면 작업 기록에 커밋을 적는다. 인증·개인 식별 파일은 공유하지 않는다.
- 정상 탐색 상태에서는 사용 조건에 따라 자동 선택할 수 있다. 목록에 보이지 않으면 SKILL.md 경로를 지정해 직접 읽게 하고 재시작 후 다시 확인한다. 현재 세션에서 자동 발견됐다고 가정하지 않는다.

Codex의 저장소 스킬 탐색과 SKILL.md 형식은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)를 참고한다. 다른 에이전트 도구를 쓰면 해당 도구의 스킬 탐색 방식도 확인한다.
