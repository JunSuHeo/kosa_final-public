## 근거·결정

- 루트/PRJ `AGENTS.md`, `PRJ/rules/project.md`, `PRJ/rules/infra.md`, workflow 실행기·이슈 댓글·게시 검증 코드와 관련 테스트를 확인했다.
- 이전 조사에서 격리 기본 점검 실패가 종료 코드·stderr 없이 `unavailable`로 변환되는 경로를 확인했다.
- HOME 아래 임시 폴더에 허용과 금지 규칙이 겹치는 정책 생성은 Linux에서 재현했다. 이번 macOS 실패의 실제 거부 규칙은 미확인이다.
- 사용자 승인: 임시 경로 고정, 오류 보존, 기존 실행·PR 정책 유지. 코딩 전 격리 점검과 4번 회귀 검증 추가는 제외한다.
- 이번 작업은 자동 테스트를 추가하거나 실행하지 않고 문법·diff·호출 경로를 정적으로 확인한다. 테스트 중심 스킬의 테스트 단계보다 사용자 요청을 우선한다.
- 깨끗한 원래 checkout에 작업 브랜치를 생성해 직접 구현한다. 별도 worktree·위임·커밋·원격 게시는 요청 범위에 추가하지 않는다.

## 결과·인계

- 승인된 1~3번을 구현했다. 격리 점검은 코딩 후에 수행하고 테스트 실패·실행 불가 후 일반 PR 생성 조건을 유지했다.
- 실패 시 `isolation_stage`, `return_code`, `stdout`, `stderr`로 다음 원인을 확인할 수 있다. 격리 점검의 종료 코드는 실제 백엔드 테스트의 종료 코드와 구분한다.
- 실제 macOS 샌드박스·모델·DB·PR 게시는 미실행이다. macOS 초기화 및 백엔드 테스트 성공은 아직 보장하지 않는다.
- 구현 후 사용자가 PR 게시를 추가 요청했다. 변경을 커밋·푸시하고 최신 `origin/main`을 기준으로 일반 PR을 전달한다. 테스트 제외 요청은 유지한다.
