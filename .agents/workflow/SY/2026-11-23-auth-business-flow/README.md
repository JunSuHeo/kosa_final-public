## 단계별 인계

기존 작업 d3ca1a7을 기준으로 `/tmp/kosa-auth-journey`, `feat/auth-stability-business-flow`에서 구현했다. 원본 작업 폴더의 main은 변경하거나 병합하지 않았다. 기존 요청에 따라 새 브랜치에 커밋·푸시하며 작업 폴더는 후속 리뷰용으로 보존한다.

인증 안정화4건, 같은 탭의 임시 입력·한글 Enter 보호, 업무 선택·대화·검토·확인본·재개 흐름을 반영했다. 현업의 명시적 확인 전에는 확인본을 변경하지 않는다. API·실행·화면 계약과 관련 규칙도 갱신했다. 상세 변경과 리뷰 근거는 [담당자 기록](agents/)에 남겼다.

## 중간 검증·리뷰

- 기준 backend61통과. 인증·진행 상태 변경 후 root의 격리 전체 재빌드는105통과(77.73초, 기존 TestClient 경고1).
- 브라우저 첫 통합은35통과/1실패. 빈 확인본 선택 시 기존 초안의 검토 메뉴가 숨겨지는 원인을 수정했다.
- 인증 독립 리뷰에서 대량 신규 이력의 cursor 간극, superseded 작업 ID 고착, 비밀번호가 바뀐 재시도의 거짓 성공을 찾아 회귀 검증했다. 미완료 계정 생성은 동일 메타데이터의 새 작업으로 같은 account/Auth UID를 복구하며 오래된 작업은 차단한다.
- 현업 독립 리뷰에서 기존 초안 대체, 늦은 다른 프로젝트 응답, 보관된 질문 답변, 응답 유실 뒤 중복 생성, 브라우저 이력 이동 경로를 보완했다.
- 실제 격리 Docker nginx/직접API 요청에서 위조 XFF가 무시되고 실제 주소의 제한 카운터가 증가함을 확인했다. 서비스 DB/모델/API키는 사용하지 않았다.
- 인증 경계 테스트는 소스 모듈 import를 제거해 실제 관리 화면에서 조작하며 production dist15개가 통과했다.
- 별도 현업 replay17개는 테스트 자체가 통과했지만 실행 중 root의 스크립트 수정으로 명령이127 종료됐다. 이를 최종 통과로 취급하지 않고 코드/스크립트를 고정해 다시 전체 검증한다.
- 이후 격리 production 전체 E2E53개가4.4분에 통과했고 테스트 컨테이너·볼륨·네트워크를 정리했다. 마지막 지연 응답 수정은 별도15개 회귀 검증과 build를 통과했다.
- 최종 독립 리뷰에서 실패 작업 재시도의 멱등 ID·미전송 입력 검사 누락과 성공한 대화 이후의 과거 실패 표시를 발견했다. 해당 경로의 회귀 테스트를 추가하고 최종 전체 검증을 다시 실행한다.
- 세 건 모두 한정 재검토에서 ADDRESS 판정. 최종 backend 전체109개가81.02초에 통과했고 격리 자원을 정리했다. 최종 frontend build와 계약3개·예제2개 검증도 통과했다. production 전체60개도4.1분에 통과했다. 이 최종 결과가 앞선 중간 검증을 대체한다.
