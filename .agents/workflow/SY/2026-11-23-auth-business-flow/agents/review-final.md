# 최종 통합 리뷰

- 대상: d3ca1a7 기준 전체 구현 패치, 승인된 plan.md
- 방식: 독립 에이전트의 읽기 전용 정적 검토. 실제 Supabase·운영 DB·모델은 사용하지 않음
- 최초 판정: 수정 필요

## 발견한 필수 수정

1. 완료된 discuss를 진행 상태 계산에서 제외해 과거 failed discuss가 정상 재시도 후에도 목록에 남음.
2. 실패 작업의 다시 시도 경로는 매번 새 UUID를 발급하고 후속 조회 실패를 요청 실패로 취급해 중복 요청 위험이 있음.
3. 같은 경로에서 생성·수정·보정 작업의 미전송 입력 검사를 우회할 수 있음.

root가 실제 소스에서 세 경로를 확인하고 backend/journey 담당자에게 회귀 검증과 함께 수정을 위임했다. 수정 후 한정 재검토 및 전체 격리 검증 결과를 추가한다.

## 수정·재검토 결과

- 대화 복구는 새 완료 대화가 더 이전의 대화 실패만 해소하도록 계산한다. 취소·문서 생성 실패·기존 초안은 유지한다. 신규 RED3건 확인 후 진행 상태17건 통과.
- 재시도 ID·정확한 요청을 계정/기획/원래 작업별로 임시 보관한다. 수락된 Job을 바로 반영하며 후속 조회 실패를 별도 처리하고 늦은 다른 기획 응답을 차단한다.
- 생성·재시도의 공통 진입점에서 미전송 대화·질문을 검사하고, 대화 화면의 재시도 버튼도 잠근다. 신규 RED4건 확인 후 관련 UI19건 통과.
- 동일 리뷰 담당자의 한정 정적 재검토에서 세 건 모두 ADDRESS, 잔여 필수 발견 없음. 실제 Supabase·모델 동작은 격리 검증 범위 밖으로 명시했다.
- root의 최종 전체 검증: backend109개, production 브라우저60개, TypeScript/Vite build, 계약3개·예제2개 모두 통과. 실제 DB·모델을 사용하지 않았으며 검증 자원을 정리했다.

## 앞선 현업 리뷰의 마지막 재검토

지연된 대화 전송 성공 시 캡처한 저장 키·원문을 비교해 정리하며, 새 입력은 보존한다. 지연된 승인·거절 응답은 현재 계정·프로젝트가 다르면 UI 후처리를 하지 않는다. 두 경로 모두 ADDRESS 판정. 지연 전송 두 테스트는 수정 전에도 GREEN이었으며 RED 증거로 취급하지 않는다.
