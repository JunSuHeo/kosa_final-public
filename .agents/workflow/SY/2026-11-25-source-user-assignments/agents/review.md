# 독립 코드 리뷰

- 날짜: 2026-11-25 (Asia/Seoul)
- 에이전트: review_source_assignments (읽기 전용)
- 공통 목표: 승인 계획대로 업무 연결 설정에서 유저 배정을 저장·취소하고 실패를 복구할 수 있는지 확인한다.
- 담당 파일: SourceAssignments.tsx, SourceSettings.tsx, App.tsx, hplan.css, 신규/변경 E2E와 관련 안내.
- 의존성: 구현은 주 에이전트가 담당하며 리뷰 에이전트는 파일·Git 상태를 변경하지 않는다. 이 파일은 주 에이전트가 리뷰 결과를 정리했다.

## 중요 발견과 조치

1. 저장 중 업무 전환이 컴포넌트를 해제하면 순차 저장의 나머지 요청이 중단된다. 지연된 쓰기 중 연결 선택/헤더 이동이 활성 상태임을 RED로 확인했다. 저장과 재확인 동안 해당 컨트롤을 비활성화하고 늦은 등록 콜백도 전환을 못 하도록 수정했다.
2. 선택 후 비활성화된 계정은 후속 후보 조회에서 사라져 실패 이름·이유가 숨겨진다. 실제 격리 계정을 비활성화한 뒤 실패 결과 그룹이 없음을 RED로 확인했다. 이전 계정 표시명과 실패 이유를 별도 결과로 남기고 개별 선택 취소를 제공했다.
3. 쓰기 응답만 유실되어 GET으로 성공을 확인해도 공통 오류 토스트가 남는다. 요청 반영 후 응답을 끊고 성공 상태와 오류 토스트가 동시에 표시됨을 RED로 확인했다. 일반 오류는 영역 안에서 처리하고 인증/권한 오류만 공통 처리하도록 수정했다.

## 후속 Minor

- 개발 StrictMode의 effect 중복 실행에서는 같은 업무의 늦은 최초 조회가 새 선택을 덮을 수 있다. production E2E는 이 경로를 검증하지 않으며 후속 개선으로 남긴다. 서로 다른 업무의 늦은 응답은 업무별 key로 격리하며 회귀 테스트를 수행한다.

## 검토 범위와 한계

- 기존 별도 배정 화면, 서버 트랜잭션 계약의 변경은 범위 밖이다.
- 운영 Supabase 인증·실제 모델 호출은 이번 리뷰에서 검증하지 않았다.
- reviewer는 정적 코드·테스트·계약 대조와 git diff --check를 수행했다. 주 에이전트는 중요 3건의 RED 재현 후 수정하고 최종 16개 격리 E2E와 프런트엔드 빌드 통과를 확인했다. 기존 권한 테스트 1건의 순간 상태 실패와 재실행 통과를 포함한 전체 실행 근거는 작업 README에 기록했다.
