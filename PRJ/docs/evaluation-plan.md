# Luna 반복 평가 및 운영 검증 계획

작성일: 2026-11-10. 실제 호출 전에 조건을 고정한다.

## 실제 AI 평가

- 모델: OpenRouter `openai/gpt-6-luna`, `studio.v1` / `review.v1`, reasoning low.
- 입력: 개인 독서 기록, 회의실 예약, 동네 행사 일정. 도메인별 같은 입력으로 2회, 총 6개 새 프로젝트.
- 매 실행: 생성·질문 응답 → 서버 검증 → 테스트 초안 승인 → 버튼 문구 한 개 수정 → 수정안의 다섯 역할 검토.
- 질문 선택: 모바일 옵션이 있으면 선택하고, 없으면 첫 옵션을 선택한다. 실제 질문·답변을 실행 증거에 보존한다.
- 수정: 첫 화면 버튼의 label 끝에 ` · 확인`을 붙이는 동일 규칙. 나머지 필드와 확정본이 유지되어야 한다.
- 구조 합격: 생성·수정에 blocking 0, 수정은 요청 필드만 변경, 승인 전 revision/current_version 불변, 다섯 역할 완료 및 서버 근거 검증 통과.
- 실패도 분모에 포함한다. 자동 반복 재호출로 성공한 결과만 남기지 않는다. 실행별 job·usage·시간·오류와 산출물을 저장한다.
- 비용: 공급자가 보고한 비용을 호출 단위로 합산한다. 누적 US$3 이상이면 다음 job을 시작하지 않는다. 단일 진행 중 job 비용은 사후 집계이므로 하드 결제 한도는 아니다.
- 비용 누락 대응(실제 검증 중 보완): 근거 검증 실패 역할의 usage가 저장되지 않는 것을 확인했다. 미확인 실패 호출마다 예산용 US$0.25를 예약해 보고 비용과 합산하고 다음 job 시작 여부를 판단한다. 예약액은 실제 청구액이 아니며, 결과에서는 보고 비용 하한과 비용 미확인 실패 수를 따로 표시한다. 이 예약 정책은 원래의 비용 누락 시 중단 방식을 대체한다.
- 집계: 6회 중 구조 통과 수, 단계별 실패, 호출 수, 토큰, 비용, 실행 시간. 소표본이므로 일반 성능으로 확대 해석하지 않는다.

## 사람의 품질 평가

각 실행에 대해 아래를 1~5점으로 평가하고 근거 ID/원문과 사유를 기록한다. 1은 사용이 어려움, 3은 수정 후 사용 가능, 5는 요청 목적에 바로 사용 가능이다.

| 항목 | 확인할 내용 |
| --- | --- |
| 요청 반영 | 핵심 요구사항과 제외 범위를 지켰는가 |
| 일관성 | PRD·기능·흐름·화면이 같은 제품을 설명하는가 |
| 사용 가능성 | 주요 작업을 실제로 수행할 수 있는 설계인가 |
| 검토 타당성 | 지적이 인용 근거로 뒷받침되고 수정 가치가 있는가 |

각 항목 3점 이상이고 중대한 누락이 없어야 사람 평가 통과다. 자동 구조 검사나 AI 자체 판단으로 사람 평가를 대체하지 않는다.

## 운영 검증

제품 DB와 다른 Compose 프로젝트·포트·볼륨에서 명시적 mock으로 실행한다. 실제 모델 처리량이나 운영 최대 용량을 주장하지 않는다.

- 동시 사용자 10명, 각 2개 프로젝트 생성. 소유권 교차 조회 404, 정상 요청 오류 0, 각 생성의 proposal 1개를 확인한다.
- 같은 proposal 동시 승인과 동일 역할 검토 중복 요청: revision 증가 1회, 중복 proposal/review 0.
- worker를 중단하고 저장된 partial이 있는 job을 준비한 뒤 재시작한다. partial 보존, 최종 proposal 1개, 완료 단계 재생성 여부를 확인한다.
- DB dump를 별도 DB에 복원한다. 전체 앱 테이블의 행 내용, 불변 revision trigger, 대기 job 재개와 역할 결과 보존을 확인한다.
- 각 요청·처리·복원 시간과 오류율을 기록한다. 로컬 소규모 기능 검증 합격은 데이터 누락/중복/예상 밖 오류 0, 생성 job 120초 이내 완료, 복원 120초 이내로 정한다.

## 사용성 검증의 한계

자동 브라우저 검증은 데스크톱/모바일의 재현 가능한 시나리오 증거다. 장기 사용성은 실제 사용자의 여러 날 사용 기록이 필요하며, 한 세션의 자동 검사로 완료 처리하지 않는다.
